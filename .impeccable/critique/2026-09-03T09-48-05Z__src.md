Overall Impression

The app is no longer a prototype. It is a real product with public discovery, bookings, owner tools, admin tools, monetisation, and notifications. The next maturity leap is design-system consolidation and owner workflow prioritisation.

What's Working

1. Public discovery direction is strong across homepage, Discover, and venue detail.
2. Owner/admin workspace shell is much clearer after the full-height dashboard work.
3. Booking is becoming a coherent loop across request, owner handling, customer status, and account bookings.

Priority Issues

[P1] Design system consistency is still loose
Why it matters: The product feels sprint-built in places. Different cards, tables, shadows, radii, headings, and accents reduce trust.
Fix: Create one shared Nokta card/table/control grammar and apply it across public, owner, account, and admin surfaces.
Suggested command: /impeccable extract

[P1] Navigation IA is overloaded
Why it matters: Public, account, owner, and admin routes are crowded into account navigation. It exposes internal structure instead of giving users clear modes.
Fix: Separate public browsing, customer account, owner workspace, and admin workspace more deliberately.
Suggested command: /impeccable shape

[P2] Owner dashboard has too many equal destinations
Why it matters: Owners need to know what requires attention today. Equal cards for every tool make them choose from structure rather than priority.
Fix: Put bookings needing action, profile health, and subscription/visibility opportunities first; move secondary tools lower.
Suggested command: /impeccable polish

[P2] Admin tables need one reusable table system
Why it matters: Admin pages risk feeling individually built and inconsistent.
Fix: Standardise density, headers, filters, empty states, status badges, action menus, and pagination.
Suggested command: /impeccable extract

[P2] Calendar status styling has detector issues
Why it matters: Thick side borders and gray-on-amber read as generic and reduce polish.
Fix: Replace border-l-4 status strips with quieter badge/fill treatments and improve amber text color.
Suggested command: /impeccable polish

[P3] Public-to-owner conversion needs a sharper story
Why it matters: Claim banners, for-venues, featured placements, billing, and analytics exist, but the commercial narrative is spread out.
Fix: Make the owner journey clearly say: claim profile, manage bookings, improve visibility, measure value.
Suggested command: /impeccable clarify

Persona Red Flags

First-time customer: The product promise is broadening beyond shisha, but some language still makes it unclear whether Nokta is for shisha, venues generally, bookings, or recommendations.

Venue owner: The owner dashboard has tools, but not enough “what needs attention now” prioritisation.

Admin user: Table and filter styles vary enough that each admin page can feel like a different mini-app.

Mobile customer: Venue detail and booking are much better, but dense metadata and sticky CTAs still need regular real-device checks.

Minor Observations

2. Admin and owner sidebars are close but not fully unified.
3. Owner Availability nav is still tied to sheesha-test-lounge in the critique signal.
4. Account pages feel less premium than public venue pages.
5. Some admin labels still sound internal: Data Quality, Promotion Requests, Venue Updates.

Questions to Consider

1. Is Nokta a discovery app with owner tooling, or a venue operating system with public discovery attached?
2. Should the owner dashboard start with today’s bookings and required actions instead of section cards?
